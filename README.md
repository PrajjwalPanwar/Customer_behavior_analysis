
# Customer Shopping Behavior Analysis

An end-to-end data analytics project exploring 3,900 customer purchase records using **Python, Pandas, MySQL, and SQL**. The project adapts a PostgreSQL-based analysis workflow to MySQL while retaining the original business questions and analytical objectives.

## Project Overview

The goal of this project is to explore customer purchasing patterns and translate transaction data into useful business insights. The analysis focuses on revenue by gender and age group, discount usage, product ratings, shipping preferences, subscription status, repeat purchasing, and product performance across categories.

## Dataset

The analysis uses a customer shopping behavior dataset containing **3,900 purchase records** and **18 original columns**. The original data includes customer demographics, purchased products, transaction amounts, product categories, shipping preferences, discounts, subscription status, review ratings, and previous-purchase information.

During preparation, the notebook identifies **37 missing values in `Review Rating`**. These are imputed using the median review rating within each product category. The notebook then standardizes column names, creates `age_group` and `purchase_frequency_days`, and removes `promo_code_used` after checking that it duplicates `discount_applied` in this dataset. The resulting analysis table has **19 columns** and no missing values in the cleaned CSV used for the SQL result checks.

> **Dataset availability:** The raw file is expected to be named `customer_shopping_behavior.csv` and placed in the project root beside the notebook. It is not included in this repository at present. Obtain it from the original dataset source and check its licence/redistribution terms before uploading it to GitHub.

## Analysis Workflow

1. **Load the data** from `customer_shopping_behavior.csv` using Pandas.
2. **Explore the data** using shape, data types, descriptive statistics, and missing-value checks.
3. **Clean the data** by imputing missing review ratings with the category-level median and standardizing column names.
4. **Engineer features** by creating age groups and mapping purchase-frequency categories to approximate day intervals.
5. **Connect to MySQL** using SQLAlchemy and MySQL Connector/Python.
6. **Load the cleaned DataFrame** into the MySQL table `customer_shopping_behavior_cleaned`.
7. **Verify the load** by querying sample records and checking the row count.
8. **Run SQL business analysis** using the ten questions in `Customer_behavior_analysis.sql`.

## Business Questions

The SQL script addresses these ten questions:

1. What is the total purchase revenue generated by male and female customers?
2. Which customers used a discount and spent at least the average purchase amount?
3. Which products have the highest average review ratings?
4. How do average purchase amounts compare between Standard and Express Shipping?
5. How do average spend and total revenue compare between subscribers and non-subscribers?
6. Which products have the highest percentage of purchases with discounts applied?
7. How are purchase records segmented by previous-purchase count?
8. What are the three most purchased products within each category?
9. Among repeat buyers (more than five previous purchases), how many are subscribers and non-subscribers?
10. What is the purchase revenue contribution of each age group?

SQL concepts used include aggregation (`SUM`, `AVG`, `COUNT`), filtering, `GROUP BY`, subqueries, `CASE`, common table expressions (CTEs), and the `ROW_NUMBER()` window function.

## Key Findings

The following figures were calculated from the cleaned 3,900-row dataset supplied for this project. Currency values are shown in the dataset's USD purchase-amount units.

### Revenue by gender

| Gender | Total purchase revenue | Share |
|---|---:|---:|
| Male | $157,890 | 67.74% |
| Female | $75,191 | 32.26% |
| **Total** | **$233,081** | **100.00%** |

Male purchase records account for the larger share of revenue in this dataset. Revenue alone does not establish profitability or explain whether the difference is driven by customer count, purchase frequency, or average order value.

### Discount use and purchase amount

- Overall average purchase amount: **$59.76**.
- **839** records have `discount_applied = 'Yes'` and a purchase amount at or above the overall average.

### Product ratings

- Gloves: **3.86**
- Sandals: **3.84**
- Boots: **3.82**
- Hat: **3.80**
- The fifth position is tied at **3.78** among Handbag, Skirt, and T-shirt. Because the original top-five query does not specify a tie-breaker, which product appears fifth can vary by query execution plan.

### Average purchase amount by shipping type

| Shipping type | Average purchase amount |
|---|---:|
| Express | $60.48 |
| Standard | $58.46 |

Express Shipping purchases have a $2.02 higher average purchase amount in this dataset. This is an observed association, not evidence that the shipping option causes higher spending.

### Subscription status

| Subscription status | Purchase records | Average purchase amount | Total revenue |
|---|---:|---:|---:|
| No | 2,847 | $59.87 | $170,436 |
| Yes | 1,053 | $59.49 | $62,645 |

Subscribers account for approximately **26.88%** of total purchase revenue. Their average purchase amount is slightly lower than that of non-subscribers in this dataset; the results do not support a claim that subscribers spend more per purchase.

### Products with the highest discount rates

| Product | Discount rate |
|---|---:|
| Hat | 50.00% |
| Sneakers | 49.66% |
| Coat | 49.07% |
| Sweater | 48.17% |
| Pants | 47.37% |

### Previous-purchase segments

The original SQL rule labels records with one previous purchase as `New`, two to ten as `Returning`, and more than ten as `Loyal`:

| Segment label in original query | Previous purchases | Records | Share |
|---|---:|---:|---:|
| New | 1 | 83 | 2.13% |
| Returning | 2–10 | 701 | 17.97% |
| Loyal | More than 10 | 3,116 | 79.90% |

**Interpretation note:** The dataset contains no records with zero previous purchases. Therefore, the `New` label in the original query means exactly one previous purchase in this analysis; it does not represent a first-ever purchase. The label should be renamed to `Single Previous Purchase` if the SQL is revised for clearer semantics.

### Most purchased products by category

The category-level ranking identifies the highest-order product types. Ties occur in Accessories and Clothing, and Outerwear has only two product types in the supplied data. Add a secondary sort key such as `item_purchased ASC` to the `ROW_NUMBER()` ordering if a deterministic tie-break is required.

### Repeat buyers and subscription

A repeat buyer is defined here as a record with more than five previous purchases.

| Group | Records | Subscribers | Subscription rate |
|---|---:|---:|---:|
| Repeat buyers (>5 previous purchases) | 3,476 | 958 | 27.56% |
| Other buyers (≤5 previous purchases) | 424 | 95 | 22.41% |

The subscription rate is about **5.15 percentage points higher** among repeat buyers in this dataset. This is a descriptive comparison and does not establish causation.

### Revenue by age group

| Age group | Total purchase revenue | Share |
|---|---:|---:|
| Young Adult | $62,143 | 26.66% |
| Middle-aged | $59,197 | 25.40% |
| Adult | $55,978 | 24.02% |
| Senior | $55,763 | 23.92% |
| **Total** | **$233,081** | **100.00%** |

Young Adult records contribute the highest revenue, although revenue is relatively evenly distributed across the four age groups.

## Business Recommendations

Based on the descriptive findings, possible areas for further investigation include:

- **Gender-based analysis:** Compare customer counts, average purchase amount, and purchase frequency by gender before designing targeted campaigns.
- **Discount strategy:** Examine whether discounted purchases increase order value or repeat purchasing, and assess margin impact before expanding discounts.
- **Shipping preferences:** Investigate whether customers choosing Express Shipping differ in product mix, order size, or location.
- **Subscription programme:** Review the value proposition and retention behaviour of subscribers; the current data does not show higher average purchase amounts among subscribers.
- **Customer retention:** Study the transition from one previous purchase to repeat purchasing and identify behaviours associated with loyalty.
- **Product merchandising:** Use product ratings and category-level order volumes together when prioritising products for campaigns.

These are hypotheses and recommendations for further analysis, not causal conclusions established by this dataset.

## How to Run the Project

### 1. Prerequisites

- Python 3.10 or newer
- Jupyter Notebook or JupyterLab
- MySQL Server 8.0 or newer
- MySQL Workbench (optional)

### 2. Get the dataset

Obtain the original `customer_shopping_behavior.csv` dataset from its source, subject to its licence. Place it in the same folder as `Customer_behavior_analysis.ipynb`:

```text
Customer_behavior_analysis/
├── customer_shopping_behavior.csv
├── Customer_behavior_analysis.ipynb
└── Customer_behavior_analysis.sql
```

The notebook expects the CSV filename shown above. If the file is stored elsewhere, update the notebook's relative `data_path` accordingly.

### 3. Install Python dependencies

Run in a terminal or notebook cell:

```bash
pip install pandas sqlalchemy mysql-connector-python jupyter
```

### 4. Create the MySQL database

In MySQL Workbench or a MySQL client, run:

```sql
CREATE DATABASE IF NOT EXISTS customer_shopping_db;
```

The notebook is configured for a local MySQL server at `localhost:3306`, using the MySQL account `root` and database `customer_shopping_db`. Adjust the connection settings for your own environment. The notebook prompts for the password with `getpass`; do not hardcode or commit passwords.

### 5. Run the notebook

Start Jupyter from the project directory so the relative dataset path resolves correctly:

```bash
jupyter notebook
```

Open `Customer_behavior_analysis.ipynb` and run the cells from top to bottom. The notebook prepares the data and loads the cleaned DataFrame into the MySQL table:

```text
customer_shopping_behavior_cleaned
```

The notebook's MySQL export uses `if_exists='replace'`, which drops and recreates that table. Use this only when you intend to refresh the analysis table.

### 6. Run the SQL analysis

After the notebook has created and populated `customer_shopping_behavior_cleaned`, open `Customer_behavior_analysis.sql` in MySQL Workbench, select the `customer_shopping_db` schema, and execute the queries. The SQL file is written for MySQL, not PostgreSQL.

## Limitations

- The results describe this 3,900-record dataset and may not generalise to other retailers, periods, or customer populations.
- The analysis is descriptive; it does not establish causal relationships.
- The `New` segment in the original SQL is defined as exactly one previous purchase because the dataset contains no zero-previous-purchase records.
- Ties in product-rating and category-ranking queries require explicit secondary ordering for fully deterministic results.
- The dataset file is not currently included in the repository; users must obtain it separately and comply with its licence.
